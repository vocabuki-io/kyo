# journal-ingest ─ 設置手順書

きょう/とい で答えた内容を、ジャーナルに自動で送るための仕組みです。
はじめて読む人向けに、省略せずに書いてあります。

**かかる時間**：だいたい25分。

**全体の流れ**

```
第1章  GitHubのトークンを作る
第2章  Workerを置く
第3章  合言葉を決めて登録する
第4章  アプリ側に設定する
第5章  動くか試す
第6章  次の1マスをClaudeに選ばせる（あとからでいい）
```

---

# 第1章 GitHubのトークンを作る

Workerがジャーナルに書き込むための鍵を作ります。

## 1-1. GitHubを開く

パソコンでブラウザを開きます。
アドレスを入れるところに、次の文字を打ちます。

```
github.com/settings/personal-access-tokens
```

キーボードの `Enter` キーを1回押します。

ログインしていない場合は、メールアドレスとパスワードを入れて
「**Sign in**」ボタンを1回クリックします。

## 1-2. 新しいトークンを作る

画面の右上に「**Generate new token**」という緑色のボタンがあります。1回クリックします。

## 1-3. 中身を決める

次の4か所を設定します。

**Token name**（名前の欄）に、次の文字を打ちます。

```
journal-ingest
```

**Expiration**（期限）は、リストから「**No expiration**」を選びます。
（期限を付けると、その日が来たときに動かなくなります）

**Repository access** という項目で、
「**Only select repositories**」の丸いボタンを1回クリックします。

その下に「**Select repositories**」というボタンが出ます。1回クリックして、
`journal` を1回クリックします。

## 1-4. 権限を与える

画面を下にスクロールします。

「**Repository permissions**」という見出しがあります。1回クリックして開きます。

たくさん項目が並んでいます。その中から「**Contents**」を探します。

「Contents」の右にあるリストを1回クリックして、
「**Read and write**」を1回クリックします。

## 1-5. 作る

画面をいちばん下までスクロールします。

「**Generate token**」という緑色のボタンを1回クリックします。

確認の画面が出たら、もう一度「**Generate token**」を1回クリックします。

## 1-6. コピーする

`github_pat_` で始まる長い文字が出ます。

その右にあるコピーのマークを1回クリックします。

**この文字は、この画面を閉じると二度と見られません。**
メモ帳を開いて、`Ctrl` + `V`（Macなら `command` + `V`）で貼っておきます。

# 第2章 Workerを置く

## 2-1. Cloudflareを開く

ブラウザで新しいタブを開きます。
アドレスを入れるところに、次の文字を打ちます。

```
dash.cloudflare.com
```

キーボードの `Enter` キーを1回押します。

メールアドレスとパスワードを入れて「**Log in**」ボタンを1回クリックします。

## 2-2. Workerを作る

画面の左側のメニューから「**Compute (Workers)**」または
「**Workers & Pages**」という文字を1回クリックします。

「**Create**」という青いボタンを1回クリックします。

上のほうに「**Workers**」と「Pages」という2つのタブがあります。
**Workers** のほうを1回クリックします。

「**Start with Hello World!**」という項目の「**Get started**」を1回クリックします。

## 2-3. 名前を決める

「Name」の欄の文字を全部消して、次の文字を打ちます。

```
journal-ingest
```

「**Deploy**」という青いボタンを1回クリックします。

30秒ほど待ちます。

## 2-4. アドレスを控える

`https://journal-ingest.○○○.workers.dev` というアドレスが出ます。

`○○○` の部分は人によって違います。
**このアドレスを、あとで使います。** メモ帳に貼っておきます。

## 2-5. コードを差し替える

画面に「**Edit code**」というボタンがあります。1回クリックします。

コードを書く画面が開きます。

左側に `worker.js` というファイルがあります。1回クリックします。

右側の文字を全部選びます（`Ctrl` + `A`、Macなら `command` + `A`）。

キーボードの `Delete` キーを1回押します。

`journal-ingest/src/index.js` の中身を全部コピーして、貼ります（`Ctrl` + `V`）。

画面の右上の「**Deploy**」ボタンを1回クリックします。

確認が出たら、もう一度「**Deploy**」を1回クリックします。

左上の「**←**」を1回クリックして、元の画面に戻ります。

# 第3章 合言葉を決めて登録する

## 3-1. 合言葉を作る

アプリとWorkerだけが知っている文字を決めます。
**推測されない長い文字**にします。

例（これはそのまま使わず、自分で適当に打ち直してください）：

```
kyou-toi-9f3k2mQx7pLa4Vn8
```

メモ帳に貼っておきます。

日本語でも動きますが、打ち間違いが起きにくいので半角の英数字をすすめます。

## 3-2. Workerの設定画面へ行く

Cloudflareの `journal-ingest` の画面で、
上のほうにある「**Settings**」というタブを1回クリックします。

## 3-3. 変数を2つ足す

「**Variables and Secrets**」という見出しを探します。

「**Add**」というボタンを1回クリックします。

- **Type** は「**Text**」を選びます
- **Variable name** に `GITHUB_OWNER` と打ちます
- **Value** に、自分のGitHubのユーザー名を打ちます

「**Add**」を1回クリックします。

もう一度「**Add**」というボタンを1回クリックします。

- **Type** は「**Text**」を選びます
- **Variable name** に `GITHUB_REPO` と打ちます
- **Value** に `journal` と打ちます

「**Add**」を1回クリックします。

## 3-4. 秘密の値を2つ足す

もう一度「**Add**」というボタンを1回クリックします。

- **Type** は「**Secret**」を選びます
- **Variable name** に `GITHUB_TOKEN` と打ちます
- **Value** に、第1章の1-6でコピーした `github_pat_` の文字を貼ります

「**Add**」を1回クリックします。

もう一度「**Add**」というボタンを1回クリックします。

- **Type** は「**Secret**」を選びます
- **Variable name** に `INGEST_TOKEN` と打ちます
- **Value** に、3-1で決めた合言葉を貼ります

「**Add**」を1回クリックします。

## 3-5. 保存する

画面の下のほうにある「**Deploy**」ボタンを1回クリックします。

## 3-6. 入れなくてもいいもの

次の3つは、入れなくても動きます。変えたいときだけ足します。

| 名前 | Type | 意味 | 入れないとき |
|---|---|---|---|
| `GITHUB_BRANCH` | Text | 書き込むブランチ | リポジトリの既定のブランチ |
| `JOURNAL_DIR` | Text | 置き場所のフォルダ | リポジトリの直下 |
| `ALLOWED_ORIGIN` | Text | 送信を許すアドレス | どこからでも（合言葉で守る） |

# 第4章 アプリ側に設定する

## 4-1. きょうを開く

iPhoneのホーム画面で「**きょう**」のアイコンを1回タップします。

## 4-2. 設定を開く

画面の右上に「**未設定**」という文字のボタンがあります。1回タップします。

## 4-3. 入れる

- 上の欄に、第2章の2-4で控えたアドレスを打ちます

```
https://journal-ingest.○○○.workers.dev
```

- 下の欄に、第3章の3-1で決めた合言葉を打ちます

「**決定**」を1回タップします。

## 4-4. 確認する

右上の文字が「**送信済**」に変わっていれば成功です。

# 第5章 動くか試す

## 5-1. 質問に1つ答える

画面のいちばん下の「**とい　↓**」を1回タップします。

質問が出たら、下の入力欄に何か打ちます。

真ん中の丸いボタンを1回タップします。

## 5-2. 送られたか見る

上の「**↑　きょう**」を1回タップして戻ります。

右上が「**送信済**」なら、もう送られています。

## 5-3. ジャーナルを見る

パソコンでブラウザを開き、次のアドレスを打ちます。

```
github.com
```

キーボードの `Enter` キーを1回押します。

左側のリポジトリ一覧から `journal` を1回クリックします。

`2026-08.md` のような、今月のファイルを1回クリックします。

いちばん下に、さっき答えた内容が入っていれば成功です。

# 第6章 次の1マスをClaudeに選ばせる

「できた」を押すと、Claudeがジャーナルとカレンダーを読み直して、
次の1マスを選んでくれるようにします。

**やらなくても、ここまでの追記はそのまま動きます。**
その場合、1マスは1日2回の自動更新のときだけ入れ替わります。

## 6-1. なにが起きるか

```
「できた」を押す
  → メモを書く
  → ジャーナルに【1マス完了】として入る
  → Worker が kyo の GitHub Actions を起こす
  → Claude がジャーナルとカレンダーを読んで、次の1マスを選ぶ
  → 画面に出る
```

出るまで**2分から4分**かかります。そのあいだ画面には
「Claudeが選んでいます」と経過時間が出ます。
**アプリを閉じても大丈夫です。** 次に開いたときに出ています。

## 6-2. Workerのコードを貼り直す

**この章の機能は、Workerのコードを新しくしないと動きません。**

Cloudflareに貼ったコードは、貼った時点のもので動き続けます。
GitHubのファイルを新しくしても、**Cloudflare側は勝手には変わりません。**

ブラウザで次の文字を打って `Enter` を押します。

```
dash.cloudflare.com
```

左のメニューから「**Compute (Workers)**」または「**Workers & Pages**」を
1回クリックします。

`journal-ingest` を1回クリックします。

「**Edit code**」を1回クリックします。

左側の `worker.js` を1回クリックします。

右側の文字を全部選びます（`Ctrl` + `A`、Macなら `command` + `A`）。

キーボードの `Delete` キーを1回押します。

`journal-ingest/src/index.js` の**いまの中身**を全部コピーして、貼ります（`Ctrl` + `V`）。

右上の「**Deploy**」ボタンを1回クリックします。

確認が出たら、もう一度「**Deploy**」を1回クリックします。

### 新しくなったか確かめる

ブラウザのアドレス欄に、Workerのアドレスをそのまま打って `Enter` を押します。

```
https://journal-ingest.○○○.workers.dev
```

出てきた文字の中に **`"canDispatch"`** があれば、新しくなっています。

無ければ、まだ古いままです。貼り付けからやり直します。

## 6-3. トークンに権限を足す

第1章で作ったトークンは `journal` にしか触れません。
`kyo` の Actions を起こせるように、権限を足します。

ブラウザで次の文字を打って `Enter` を押します。

```
github.com/settings/personal-access-tokens
```

`journal-ingest` という名前の行を1回クリックします。

**Repository access** の「**Select repositories**」を1回クリックして、
`kyo` を1回クリックします。`journal` と2つ選ばれた状態にします。

画面を下にスクロールして「**Repository permissions**」を開きます。

「**Actions**」を探します。右のリストを1回クリックして、
「**Read and write**」を1回クリックします。

画面をいちばん下までスクロールして、
「**Update token**」という緑色のボタンを1回クリックします。

**トークンの文字は変わりません。**
Workerの `GITHUB_TOKEN` を登録し直す必要はありません。

## 6-4. Claudeにジャーナルを読ませる

Actionsの中で動くClaudeにも、ジャーナルを読ませます。

ブラウザで、`kyo` リポジトリを開きます。

```
github.com/自分のユーザー名/kyo/settings/secrets/actions
```

「**New repository secret**」という緑色のボタンを1回クリックします。

- **Name** に `JOURNAL_TOKEN` と打ちます
- **Secret** に、第1章の1-6でコピーした `github_pat_` の文字を貼ります

「**Add secret**」を1回クリックします。

メモ帳に残していない場合は、第1章をもう一度やって新しく作ります。

## 6-5. 試す

**6-2から6-4を全部やってから**試します。どれか1つでも抜けていると出ません。

iPhoneで「きょう」を開いて、「**できた**」を1回タップします。

メモの欄が出ます。何か打って（打たなくてもいいです）「**決定**」を1回タップします。

「Claudeが選んでいます」に変わります。

そのまま待つか、アプリを閉じます。
**2分から4分後**に開くと、新しい1マスが出ています。

## 6-6. 入れなくてもいいもの

`kyo` という名前で、`main` ブランチで使っているなら、なにも足さなくて動きます。
違う場合だけ、Workerの Settings に Text で足します。

| 名前 | 意味 | 入れないとき |
|---|---|---|
| `APP_REPO` | アプリのリポジトリ名 | `kyo` |
| `APP_OWNER` | その持ち主 | `GITHUB_OWNER` と同じ |
| `APP_WORKFLOW` | 起こすワークフロー | `build.yml` |
| `APP_BRANCH` | そのブランチ | `main` |
| `DISPATCH_TOKEN` | Actions用の別トークン | `GITHUB_TOKEN` を使う |

# 第7章 うまくいかないとき

## 右上がずっと「未送信 1」のまま

送信に失敗して、端末に貯まっている状態です。
**内容は消えません。** 次に成功したときにまとめて送られます。

理由を見るには、右上のボタンを1回タップします。
設定画面のまん中あたりに、失敗した理由が小さく出ます。

Worker自体が動いているかを見るには、パソコンで次を試します。

ブラウザのアドレス欄に、Workerのアドレスをそのまま打って `Enter` を押します。

```
https://journal-ingest.○○○.workers.dev
```

`{"ok":true,...}` と出れば、Workerは動いています。
何も出ない、またはエラーが出る場合は、第2章をやり直します。

このとき `"configured":false` と出ていたら、第3章の変数が足りていません。

`"canDispatch"` という文字が**どこにも無い**場合は、
貼ったコードが古いままです。第6章の6-2で貼り直します。

## 「合言葉が違います」と出る

第3章の3-4で登録した `INGEST_TOKEN` と、
第4章の4-3で入れた文字が、1文字でも違うと出ます。

両方をメモ帳に貼って、見比べます。前後に空白が入っていないかも見ます。

## 「アドレスが違います」と出る

第4章の4-3で入れたアドレスが間違っています。
第2章の2-4で控えたものと見比べます。`https://` から始まっているかも見ます。

## 「書き込みに失敗」と出る

第1章のトークンの権限が足りていません。

- `journal` リポジトリが選ばれているか
- `Contents` が `Read and write` になっているか

この2つを見直して、第1章からやり直します。

## 「繋がりません」と出る

電波がないか、アドレスが間違っています。
電波のあるところで、右上のボタンを1回タップすると送り直します。

## 「頼めませんでした / そのアドレスはありません」と出る

**Cloudflareに貼ったコードが古いままです。**

Cloudflareのコードは、貼った時点のもので動き続けます。
GitHubのファイルを新しくしても、Cloudflare側は勝手には変わりません。

第6章の6-2をやり直して、コードを貼り直します。

## 「次の1マスを頼めません / Actions の権限がありません」と出る

第6章の6-3をやり直します。

- `kyo` がトークンの Repository access に入っているか
- `Actions` が `Read and write` になっているか

## 「次の1マスを頼めません / kyo か build.yml が見つかりません」と出る

リポジトリの名前が `kyo` ではないか、ブランチが `main` ではありません。
第6章の6-6の表を見て、Workerに `APP_REPO` や `APP_BRANCH` を足します。

## 「Claudeが選んでいます」から進まない

8分たつと「**まだ出ていません**」に変わって、
「**1マスをたのむ**」のボタンが出ます。1回タップすると頼み直せます。

それでも変わらないときは、パソコンで `kyo` リポジトリの
「**Actions**」タブを開いて、build の行を見ます。

- **行が増えていない** → 第6章の6-3をやり直します
- **赤い×** → 行を1回クリックすると理由が出ます

## 1マスがずっと同じものになる

Claudeがジャーナルを読めていません。
第6章の6-4で `JOURNAL_TOKEN` を登録したか確かめます。

Actionsの build を開いて「**fetch journal**」の行を1回クリックすると、
`JOURNAL_TOKEN が無いので、ジャーナル無しで進みます` と出ているはずです。

## 送りたくない日がある

右上の設定を開いて、合言葉の欄を空にして「決定」を1回タップします。
送信が止まります。戻すときは、また入れ直します。

止めているあいだに答えたものは、貯まりません。送られないまま消えます。

# 送られる内容

- **といの回答**：質問と答えと絵文字。「パス」したものは送りません
- **1マスの完了**：「【1マス完了】〜」と、そのとき書いたメモ
- **なんでもメモ**：「きょう」のいちばん下の欄に書いたもの

`journal` リポジトリの `YYYY-MM.md` に、こういう形で足されます。

```
## 2026-08-27 19:03

【とい】8/27
・今なにしてる? → コード書いてる 😊
・なに食べた? → ラーメン

---

## 2026-08-27 21:40

【1マス完了】垂れ幕の即日依頼を考える
印刷屋に電話した。明日10時に見積もりが来る

---

## 2026-08-27 22:10

【メモ】1日1回ガチャサイト
1等：1万円をPayPayで渡す
```

送るタイミングは次の4つです。

1. 答えてから1〜2秒後
2. 質問が全部終わったとき
3. アプリを閉じたとき
4. アプリを開いたとき（前に失敗したぶんがあれば）

**電波がなくても失われません。** 端末に貯まって、次に繋がったときに送られます。

同じものが二度送られても、ジャーナルには一度しか入りません。
